# OurPaintDCM

`OurPaintDCM` - это C++ библиотека для решения геометрических ограничений в 2D-эскизах CAD. Она хранит геометрию, связывает объекты ограничениями, строит систему уравнений и решает её в разных режимах: глобально, локально по компоненте и интерактивно во время перетаскивания.

Проект ориентирован на сценарий параметрического эскизника. Пользователь создаёт точки, линии, окружности и дуги после этого CAD добавляет геометрические ограничения, решатель решает положение зависимых объектов и приложение получает новую координату

## Что уже есть

### Геометрические примитивы

- `Point2D`
- `Line`
- `Circle`
- `Arc`

Все примитивы можно создавать либо напрямую по координатам, либо через уже существующие опорные точки по их `ID`.

### Поддерживаемые ограничения

Сейчас в высокоуровневом API доступны:

- расстояние между двумя точками;
- совпадение двух точек;
- расстояние от точки до линии;
- принадлежность точки линии;
- принадлежность точки окружности;
- расстояние от линии до окружности;
- принадлежность линии окружности;
- заданный радиус или диаметр окружности;
- равенство длин отрезков;
- равенство радиусов окружностей;
- точка в середине отрезка (`pointAtMidpoint(pointId, lineId)`);
- симметрия двух точек относительно прямой, горизонтальной/вертикальной оси или точки;
- касание несущей прямой и окружности с выбранной стороной;
- внешнее и два варианта внутреннего касания окружностей;
- касание дуги и линии или двух дуг в выбранных концах;
- параллельность линий;
- перпендикулярность линий;
- фиксированный угол между линиями;
- вертикальность линии;
- горизонтальность линии;
- фиксация точки;
- фиксация линии;
- фиксация окружности.

`LineInCircle` уже присутствует в перечислениях и дескрипторах, но через единый `addRequirement()` в текущей версии ещё не поддержан(в будущем исключена)

### Что умеет менеджер системы

Класс `DCMManager` даёт единый API для:

- добавления и удаления геометрии;
- обновления координат точек и радиусов окружностей;
- добавления, удаления и изменения параметров ограничений;
- разбиения сцены на компоненты связности;
- локального решения только затронутой части эскиза;
- диагностики состояния системы по Якобиану.

### Режимы решения

- `GLOBAL` - решить всю систему целиком;
- `LOCAL` - решить только одну компоненту связности;
- `DRAG` - пересчитывать систему при редактировании геометрии, удобно для интерактивного перетаскивания.

## Вырожденная геометрия и ограничения

Отрезок нулевой длины считается схлопнувшимся. Поведение зависит от смысла ограничения:

| Ограничение | Поведение при вырождении |
| --- | --- |
| `pointOnLine` | Схлопнувшийся отрезок считается своей первой конечной точкой; требуется совпадение с ней. Для ненулевого отрезка проверяется принадлежность несущей прямой. |
| `pointLineDist` | Для схлопнувшегося отрезка используется евклидово расстояние до первой конечной точки. Для ненулевого сохраняется знаковое расстояние до несущей прямой. |
| `pointOnPoint`, `pointPointDist` | Совпадение точек допустимо; оно удовлетворяет только нулевому расстоянию. |
| `lineCircleDist` | Схлопнувшийся отрезок считается точкой; проверяется расстояние до центра минус радиус и заданный зазор. |
| `lineOnCircle` | Совпадающие концы допустимы, если их общая точка лежит на окружности. |
| `pointOnCircle` | Точка в центре допустима как исходное положение; свободная точка может выйти из него пробными шагами LM. Радиус должен быть положительным. |
| `equalLength` | Нулевые длины допустимы: два нулевых отрезка удовлетворяют равенству. Свободный отрезок может развернуться из нулевого состояния. |
| `pointAtMidpoint` | Две независимые линейные невязки по X и Y. Нулевой отрезок допустим; середина совпадает с его концами. У свободной точки на закреплённом отрезке остаётся 0 DoF. |
| `symmetricAboutLine` | Нулевая длина оси неопределённа; совпадение симметричных точек допустимо на оси. |
| `lineCircleTangent` | Нулевая длина линии неопределённа. Радиус положителен, сторона сохраняется. |
| `circleCircleTangent` | При внутреннем касании содержащий радиус строго больше; совпадающие окружности не принимаются. При внешнем совпавшие центры допустимы как исходное положение. |
| `arcLineTangent`, `arcArcTangent` | Выбранные концы соединяются; нулевые радиусы контакта и нулевая длина линии неопределённы. |
| `circleRadius`, `circleDiameter`, `equalRadius` | Все участвующие радиусы должны быть конечными и строго положительными. Центры этими требованиями не ограничиваются. |
| `lineLineParallel`, `lineLinePerpendicular`, `lineLineAngle` | Обе линии должны иметь ненулевую длину. Направление схлопнувшейся линии неопределено. Параллельность и перпендикулярность проверяются по нормированным векторам. |
| `horizontal`, `vertical` | Требуется ненулевая линия с определённым направлением. |
| `arcCenterOnPerpendicular` | Требуется ненулевая хорда; при совпадающих концах её серединный перпендикуляр неопределён. Невязка — знаковое расстояние до него. Центр в середине ненулевой хорды допустим. |
| `fixPoint`, `fixLine`, `fixCircle` | Фиксация сохраняет координаты; нулевая длина фиксированной линии допустима сама по себе. Радиус окружности всегда должен быть положительным. |
| `lineInCircle` | Пока не поддерживается единым интерфейсом. |

Эти правила одинаковы для `GLOBAL`, выбранной компоненты в `LOCAL` и пересчёта в `DRAG`.
Активное неопределённое ограничение имеет невязку `+∞`; `solve()` возвращает `false`.
Если оно неопределено перед оптимизацией, попытка решения завершается сразу с восстановлением
состояния на входе в `solve()`. После изменения геометрии можно повторить решение.
Обычные ограничения с весом `0` отключены и не проверяются; фиксация и совпадение точек требуют веса `1`.

## Стационарные исходные положения

Если ошибка ненулевая, а градиент LM равен нулю, решатель проверяет ограниченный набор
детерминированных пробных шагов по свободным координатам. В гладком экстремуме масштаб
шага учитывает отрицательную кривизну полной целевой функции; для совпадающих точек
используется норма невязок. Принимается только конечный шаг, уменьшающий общую взвешенную
ошибку, после чего LM продолжает решение. Неудачные пробы восстанавливают координаты.

Это позволяет решать параллельность из строго перпендикулярного положения,
перпендикулярность из строго параллельного положения, углы из коллинеарного положения
и положительное расстояние между первоначально совпадающими свободными точками.
Правила действуют в `GLOBAL`, `LOCAL` и `DRAG`; фиксированные координаты и временные
блокировки DRAG не входят в пробный шаг. Сохраняется обычная попытка DRAG без временных
блокировок, если они заняли все оставшиеся степени свободы.

Успех по-прежнему требует выполнения ограничений. Неопределённые направления нулевых
линий и несовместимые ограничения возвращают `false`; поиск ограничен бюджетом итераций LM.

## Сборка

Требования:

- CMake `3.26+`
- компилятор с поддержкой `C++20`
- доступ в интернет при первой сборке для загрузки `Eigen` и `GoogleTest`

Сборка библиотеки:

```bash
git clone --recurse-submodules https://github.com/OurPaintTeam/OurPaintDCM.git
cd OurPaintDCM
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build
```

Запуск тестов:

```bash
cd build
ctest --output-on-failure
```

Проект собирает статическую библиотеку `OurPaintDCM`.

## Быстрый старт

Ниже минимальный сценарий: создать две точки, задать между ними расстояние и решить систему.

```cpp
#include "DCMManager.h"

using namespace OurPaintDCM;
using namespace OurPaintDCM::Utils;

int main() {
    DCMManager dcm;

    auto p1 = dcm.addFigure(FigureDescriptor::point(0.0, 0.0));
    auto p2 = dcm.addFigure(FigureDescriptor::point(30.0, 0.0));

    dcm.addRequirement(RequirementDescriptor::pointPointDist(p1, p2, 50.0));

    dcm.setSolveMode(SolveMode::GLOBAL);
    const bool ok = dcm.solve();

    if (!ok) {
        return 1;
    }

    auto a = dcm.getFigure(p1);
    auto b = dcm.getFigure(p2);

    // Здесь CAD может забрать новые координаты и перерисовать эскиз.
    return 0;
}
```

## Как пользоваться

### 1. Создать геометрию

Можно добавлять объекты по координатам:

```cpp
auto p  = dcm.addFigure(FigureDescriptor::point(10.0, 20.0));
auto l  = dcm.addFigure(FigureDescriptor::line(0.0, 0.0, 100.0, 10.0));
auto c  = dcm.addFigure(FigureDescriptor::circle(40.0, 40.0, 25.0));
auto a  = dcm.addFigure(FigureDescriptor::arc(0.0, 0.0, 10.0, 0.0, 5.0, 5.0));
```

Или собирать составные объекты из уже существующих точек:

```cpp
auto p1 = dcm.addFigure(FigureDescriptor::point(0.0, 0.0));
auto p2 = dcm.addFigure(FigureDescriptor::point(100.0, 0.0));
auto line = dcm.addFigure(FigureDescriptor::line(p1, p2));
```

### 2. Добавить ограничения

Примеры:

```cpp
dcm.addRequirement(RequirementDescriptor::horizontal(line));
dcm.addRequirement(RequirementDescriptor::vertical(otherLine));
dcm.addRequirement(RequirementDescriptor::pointOnLine(p1, line));
dcm.addRequirement(RequirementDescriptor::pointPointDist(p1, p2, 100.0));
dcm.addRequirement(RequirementDescriptor::lineLineParallel(line1, line2));
dcm.addRequirement(RequirementDescriptor::fixPoint(p1));
```

Размерные требования и принадлежность окружности:

```cpp
dcm.addRequirement(RequirementDescriptor::pointOnCircle(pointId, circleId));
dcm.addRequirement(RequirementDescriptor::circleRadius(circleId, 10.0));
dcm.addRequirement(RequirementDescriptor::circleDiameter(otherCircleId, 20.0));
dcm.addRequirement(RequirementDescriptor::equalLength(line1Id, line2Id));
dcm.addRequirement(RequirementDescriptor::equalRadius(circleId, otherCircleId));
```

Радиус и диаметр задаются конечным положительным числом. Диаметр сохраняется в дескрипторе
в исходных единицах, а математическая невязка равна `r - D/2`: допуск `solve()` для обоих
размеров относится к радиусу. Поэтому эквивалентные размеры `radius(10)` и `diameter(20)`
имеют одинаковый вес в решении. При обновлении диаметра через `updateRequirementParam()`
передаётся новое значение диаметра. Центр остаётся свободным; это размерное требование,
которое поддерживает обычные веса и совместное решение, включая проверку противоречий.

Равенство длин не задаёт численную длину, а равенство радиусов не задаёт численный радиус.
В невырожденном положении два свободных отрезка равной длины имеют 7 DoF, две свободные
окружности равного радиуса — 5 DoF, окружность с заданным размером — 2 DoF, а свободная
точка на закреплённой окружности — 1 DoF. Размеры и равные радиусы пока поддерживаются
для окружностей; дуги в этих требованиях не принимаются.

Середина и симметрия задаются двумя независимыми строками:

```cpp
dcm.addRequirement(RequirementDescriptor::pointAtMidpoint(pointId, lineId));
dcm.addRequirement(RequirementDescriptor::symmetricAboutLine(p1, p2, axisLineId));
dcm.addRequirement(RequirementDescriptor::symmetricAboutHorizontal(p1, p2, 5.0)); // y=5
dcm.addRequirement(RequirementDescriptor::symmetricAboutVertical(p1, p2, -2.0)); // x=-2
dcm.addRequirement(RequirementDescriptor::symmetricAboutPoint(p1, p2, centerId));
```

Ось-прямая может двигаться, но её концы должны различаться. Совпавшие симметричные
точки допустимы на оси. При закреплённой оси у двух свободных точек остаётся 2 DoF.
Центральная симметрия использует те же математические уравнения, что и середина.
Координату горизонтальной/вертикальной оси можно менять через `updateRequirementParam()`.

Касание `lineCircleTangent(lineId, circleId, TangencySide::POSITIVE)` относится к
бесконечной несущей прямой. `POSITIVE` означает центр слева от направления первого
конца линии ко второму, `NEGATIVE` — справа. Точка контакта может находиться за
концами отрезка. Сторона сохраняется в требовании и снимке; её можно переключить
через `updateLineCircleTangencySide()`. Нулевая длина линии делает касание неопределённым.

`circleCircleTangent(c1, c2, CircleTangencyKind::EXTERNAL)` задаёт внешнее касание.
Для внутреннего используются `FIRST_CONTAINS_SECOND` или `SECOND_CONTAINS_FIRST`.
Содержащая окружность должна иметь строго больший радиус; неверный порядок и
совпадающие окружности дают неопределённое требование. Начальная геометрия должна
удовлетворять этому порядку. Вид хранится в снимке и переключается через
`updateCircleCircleTangencyKind()`. У двух свободных окружностей остаётся 5 DoF
в обычном положении; совпавшие центры при внешнем касании могут раздвинуться при решении.

Касания дуг соединяют выбранные концы и добавляют одну строку касания:

```cpp
dcm.addRequirement(RequirementDescriptor::arcLineTangent(
    arcId, Endpoint::SECOND, lineId, Endpoint::FIRST));
dcm.addRequirement(RequirementDescriptor::arcArcTangent(
    arcId, Endpoint::SECOND, otherArcId, Endpoint::FIRST));
```

Общие концы используют одни координаты; отдельные концы объединяются так же, как
при `pointOnPoint`. При положительном весе соединение активно, вес умножает строку
касания; нулевой вес отключает и соединение, и касание. Внутренние условия дуг
сохраняются. Нулевой радиус в контакте и нулевая длина линии делают касание
неопределённым. Выбор концов хранится в снимках и меняется через
`updateArcTangencyEndpoints()`. Направление обхода и выбор плавного продолжения
пока не задаются: принимаются коллинеарные радиусы обоих направлений.

### 3. Запустить решение

```cpp
dcm.setSolveMode(SolveMode::GLOBAL);
bool ok = dcm.solve();
```

Если нужно решать только часть эскиза:

```cpp
auto component = dcm.getComponentForFigure(line);
if (component.has_value()) {
    dcm.setSolveMode(SolveMode::LOCAL);
    dcm.solve(component.value());
}
```

### 4. Забрать результат обратно в CAD

После `solve()` обновлённые координаты уже записаны в геометрию внутри `DCMManager`. Их можно получить через `getFigure()`:

```cpp
auto desc = dcm.getFigure(line);
auto p1Id = desc->pointIds[0];
auto p2Id = desc->pointIds[1];

auto p1Desc = dcm.getFigure(p1Id);
auto p2Desc = dcm.getFigure(p2Id);
```

То же касается окружностей и дуг

### 5. Обновлять геометрию при редактировании

Для интерактивного сценария удобно использовать режим `DRAG`:

```cpp
dcm.setSolveMode(SolveMode::DRAG);
dcm.updatePoint(PointUpdateDescriptor(p1, 120.0, 35.0));
```

В этом режиме `updatePoint()` и `updateCircle()` автоматически пытаются пересчитать затронутую компоненту.

## Диагностика системы

Низкоуровневая система ограничений умеет:

- вычислять вектор невязок;
- строить Якобиан;
- вычислять `J^T J`;
- определять состояние системы.

Типичный сценарий диагностики:

```cpp
auto status = dcm.getRequirementSystem().diagnose();
auto report = dcm.getRequirementSystem().diagnoseDetailed();
if (report.degreesOfFreedom) {
    std::size_t freeDoF = *report.degreesOfFreedom;
}
```

Диагностика `RequirementSystem` охватывает всю геометрию эскиза, включая объекты без требований.
Например, одна зафиксированная и одна свободная точка дают `UNDER_CONSTRAINED` и две степени свободы;
`EMPTY` означает отсутствие геометрии. Для системы с явно заданной областью учитываются её фигуры
и их опорные точки. Общие точки и представители совпадений учитываются один раз,
радиус окружности — как отдельная координата, внутреннее условие дуги — как обязательное ограничение.

Отчёт содержит `variableCount`, `constraintCount`, `rank` и `degreesOfFreedom`.
Число степеней свободы равно числу координат после объединения совпадений минус ранг Якобиана
и описывает локальную линеаризацию в текущем положении. Нулевые веса отключают требования;
ненулевые веса не меняют расчёт степени определённости. Если невязки или Якобиан не определены,
статус — `SINGULAR_SYSTEM`, а `rank` и `degreesOfFreedom` не содержат значения.
После изменений через API `DCMManager` следующий вызов `getRequirementSystem()` обновляет систему.
Низкоуровневый `RequirementFunctionSystem` диагностирует только переданные ему активные требования.

Возможные состояния:

- `WELL_CONSTRAINED`
- `UNDER_CONSTRAINED`
- `OVER_CONSTRAINED`
- `SINGULAR_SYSTEM`
- `EMPTY`
- `UNKNOWN`

## Как интегрировать в свой CAD

### Рекомендуемый сценарий

На текущем этапе `OurPaintDCM` удобнее всего встраивать в CAD как исходники или как git-submodule внутри основного проекта.

#### Шаг 1. Подключить проект в CMake

```cmake
add_subdirectory(external/OurPaintDCM)

target_link_libraries(my_cad PRIVATE OurPaintDCM)
```

`OurPaintDCM` экспортирует свои include-директории через target-based CMake API, поэтому при использовании через `add_subdirectory(...)` достаточно просто линковаться с целью `OurPaintDCM` без ручного перечисления include-путей в вашем CAD.

#### Шаг 2. Сделать адаптер между объектами CAD и DCM

Обычно достаточно хранить отображения:

- `cadEntityId -> dcmFigureId`
- `cadConstraintId -> dcmRequirementId`

Тогда интеграция выглядит так:

1. Пользователь создаёт примитив в CAD.
2. CAD создаёт соответствующий `FigureDescriptor`.
3. `DCMManager` возвращает `ID`, который вы сохраняете в своей модели.
4. При добавлении ограничения CAD создаёт `RequirementDescriptor` и тоже сохраняет полученный `ID`.
5. После `solve()` CAD читает обновлённые координаты и обновляет экран.

#### Шаг 3. Выбрать правильный режим решения

- `GLOBAL` подходит для полного пересчёта эскиза после серии изменений.
- `LOCAL` удобен, если у вас несколько независимых групп геометрии.
- `DRAG` лучше всего подходит для интерактивного перемещения ручек и точек мышью.

### Практический поток для эскизника

Типичный жизненный цикл в CAD:

1. Создать в `DCMManager` фигуры, соответствующие объектам эскиза.
2. При создании зависимостей добавить ограничения через `RequirementDescriptor`.
3. Во время редактирования обновлять точки через `PointUpdateDescriptor`.
4. В `DRAG` или `LOCAL` режиме решать только нужную компоненту.
5. После решения синхронизировать новые координаты обратно в представление CAD.
